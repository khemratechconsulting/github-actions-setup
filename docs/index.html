Everything a careful setup needs

Not a copy-pasted template — the defaults follow the same practices you'd expect from a senior DevOps review.

🔍

Auto language detection

Reads package.json, requirements.txt/pyproject.toml, or go.mod — no flags needed for the common case.

🔐

Honest about auth tradeoffs

AWS authenticates via short-lived GitHub OIDC tokens. Cloudflare, Railway, Render, Vercel, and SSH deploys don't support that yet, so those use a scoped static secret instead — we tell you which is which.

🚦

Tests gate deploys

The deploy job always depends on the test job passing — a red build can never reach production.

🌎

How it works

Four steps, most of them automatic.

1

Run the script

From your project root — one command, no config file to write by hand.

2

Pick a deploy target

AWS, Vercel, Cloudflare, Railway, Render, a generic server, or tests-only if you're not ready to automate deploys yet.

3

Add the secrets it prints

The script tells you the exact names to add under Settings → Secrets and variables → Actions.

4

Push and watch it run

Open a PR to see tests run; merge to main to see the deploy job fire.
